# Acquire — 学术检索方法规范

## 1. 检索目标与来源不是固定的一张表

| 用户需求 | 关键策略与产物 |
| --- | --- |
| 快速了解陌生领域 | 代表综述+核心原始研究；关注经典与前沿，绘制初步路线，不仅按作者头衔寻找 |
| 找核心实证科学论文 | 对象 × 科学过程 × 现象/结果；保留对立结论与适用条件 |
| 找技术方法创新 | 任务 × 技术瓶颈 × 方法家族，检查创新点、基线、消融、泛化与代码 |
| 找数据/模型/代码 | 对象/变量 × dataset/product/benchmark/model；核实官方链接、版本、分辨率、许可与可用性 |
| 找某观点的文献证据 | 把断言拆成可验证命题，搜支持与不支持研究；优先直接相关研究 |
| 面向综述的可复现检索 | 先冻结协议，再分数据库翻译检索式、记录完整时间/数量/去重/筛选 |

研究主题宽泛时，先问会改变产物或标准的问题；不要固定要求用户填完所有筛选条件。期刊名、作者声望、引用量只用作发现线索，不代替相关性和方法质量。

## 2. 检索词和语法

- 拆分概念组、主题术语及英/中文同义、缩写、旧术语，记录扩展理由与来源。
- 同组通常 OR、概念组之间通常 AND；引号、通配符和 NOT 必须根据实际数据库语法调整。
- Web of Science TS、TI、AU；Scopus TITLE-ABS-KEY；CNKI 的主题/篇名/关键词等字段与语法不同；Google Scholar 不是 WoS 的语法兼容替代。
- 语义检索工具通常需要自然语言研究描述，不能把布尔检索式直接当作最佳语义查询。
- 不能因为某次检索没有结果，就说领域里不存在该研究。

## 3. 渐进式检索与深度模式

- QUICK：先确定少量高代表性的来源，标注“入门/探索性检索”；建议后续精读，不强制启动全部流程。
- FOCUSED：根据问题构造 2–4 个互补语义视角，结合反例检索和高精度纳排，不将 2–4 次视为硬科学标准。
- DEEP：结合自主深检索（可用时）、核心论文正向/反向引文、方法类别和代表团队，检查边缘子领域与不同结论是否被遗漏。
- SYSTEMATIC：事前记录问题、研究类型、时间范围、语言、数据库、完整检索式、检索日期、纳排规则、筛选流程、去重策略；协议修订必须留痕。若用户要求 PRISMA，应在符合相应报告标准及真实计数基础上输出，不能凭估计补造流程数字。

## 4. 停止与重规划

- 探索性任务：当新增搜索连续获得的关键概念/方法/代表论文很少且目标覆盖已经合理时，可以向 Router 建议停止；这属于启发式停止，必须说明范围，不能叫“完备检索”。
- 专题检索：达到用户要求的相关性、真实性和覆盖条件，或触及硬预算时停止；如果仍有空缺则 PARTIAL。
- 系统检索：依据冻结协议、实际数据库覆盖和筛选工作完成情况判断，不使用探索性饱和代替。
- 遇到明显不同研究分支时，只在用户原定 Mission 内做局部扩展；若要改变研究对象/纳排条件，则交回 Router 做重大重规划审批。

## 5. 检索审计日志

最低记录：`query_id`、工具/数据库、实际查询或 goal、查询时间、应用的过滤条件、返回数量（不臆造）、可见结果范围、关键新增术语、局限和原始产物引用。异步搜索记外部 job 引用和状态。优先保留查询记录，便于以后复检。

## 6. 候选条目可靠性

逐条区分：

- **DISCOVERED**：某工具或来源返回的候选论文（不代表已外部交叉确认）。
- **CROSSCHECKED**：标题/作者/年份/DOI 等通过独立可核对来源核验；说明来源和时间。
- **CONFLICT**：来源元数据相互矛盾，等待人工检查。

文章版本：期刊正式版、会议论文、预印本、学位论文或未知；不同 DOI 的版本之间只做关系候选，不直接合并。文献推荐优先级不构成科学质量评分；引文数随数据库时间变化，不可作为强统一证据。

## 7. 阶段与强度两轴分类（本版补充）

`EXPLORATORY / DEEPENING / TARGETED` 仅描述当前用户认知与交付场景；`QUICK / FOCUSED / DEEP / SYSTEMATIC` 描述执行强度与检索协议类型。探索型优先真实证据支持的初步领域地图再互动，定向型直接检索；已有长期 Workspace 不改变这一判断。检索年份应由关键理论/方法发展节点和当前最新文献共同确定，用户明示边界和冻结的系统综述协议优先。

## 8. 证据驱动领域地图与覆盖矩阵（本版补充）

DomainMap 中每条 `branches[].supporting_paper_ids` 必须指向候选文献的稳定记录 ID；如果没有可靠文献只可在 `uncertainties` 记录猜想，不得输出为领域客观事实。覆盖评价包括分支、年代、方法、不同观点、种子召回、不同平台新增信息及未检索来源。`REASONABLE_FOR_TASK` 不等于检索全面。

## 9. 附加 PDF 获取状态（本版补充）

原 `CandidateSet.verification.fulltext` 字段保留兼容；实际已下载/已核验/本地文件路径以单独 `pdf_acquisition_manifest` 为准。任何自动 PDF 获取均不得将 CandidateSet 的 `read_scope` 自动升级为 `FULLTEXT_ACCESSED`。必要时人工补齐后由 Router 触发新的阅读任务。
