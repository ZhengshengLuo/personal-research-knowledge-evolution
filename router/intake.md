# Intent Resolver — 任务理解与准入

## 目标
识别用户实际要完成的科研交付物，先理解，后执行。输入可以是研究主题、关键词、PDF、已有笔记或明确的知识管理请求；不可因研究领域相似而替用户改写目标。

## 内部判断维度
- `objective`：最终想知道/完成什么。
- `deliverables`：论文列表、研究图谱、逐篇报告、证据矩阵、知识记录或候选假设等。
- `scope`：对象、变量、区域、时段、研究类型、纳排标准；用户未指定的不擅自收紧。
- `research_mode`：QUICK / FOCUSED / DEEP / SYSTEMATIC。SYSTEMATIC 需独立可复现协议，不等同更多搜索调用。
- `inputs`：已知论文、PDF、研究空间、数据权限。
- `permissions/budget/acceptance`：写入许可、资源限制与交付的可检查条件。

## 澄清触发条件
如果缺少的信息会明显改变**研究问题、主要交付物、系统综述纳排标准、资源代价或正式数据操作范围**，先提出优先级最高的一项问题；其他小歧义以显式 ASSUMED 处理。只问真正决定分支的问题；不得固定要求问 3 轮或强行达到“99.99%”主观置信度。

宽泛任务示例：`研究极端天气下植被响应`，优先问“您主要想建立领域认识、寻找技术方法，还是识别争议与研究 Gap？”；答复后再看是否还有会实质改变路线的范围歧义。

## Task Readiness Gate
- 目标和可检查交付成果明确。
- 关键范围/纳排条件已确认，或可解释地维持开放。
- 主要材料/访问能力及证据缺口已知。
- 权限与必要资源边界清晰。
- 用户确认、上下文推断、默认假设分别保存：`USER_CONFIRMED`、`INFERRED_FROM_CONTEXT`、`ASSUMED`。
若不满足：`CLARIFYING`，只做安全的可逆探索；满足：`READY` 并进入规划。

## 透明交流
一段短计划即可：研究目标；主/辅助路线；当前阶段；预期交付；验证/覆盖边界；审批或预算限制。不要让用户批准每个检索词。
