# Adaptive Planner — Mission / Stage / Action

## Mission（稳定合同）
由已理解的需求固定 objective、deliverables、scope、acceptance、权限与硬预算；重大改变需说明差异并征求用户确认。工作假设可以随着证据修订，**用户委托目标不能被偷偷替换**。

## Stage（动态路线）
确定完成目标需要的主路由和可选辅助路由，分阶段定义 inputs、outputs、dependencies、evidence_requirements 和 completion_gate。只细化当前 Stage；后续在上一阶段完成后滚动细化。跨路由依赖并非强制的四步流水线。

## Action（即时操作）
选择当下可用的检索/全文/存储能力、当前检索式、待读文件和下一步核验。可并行独立检索；需要论文身份去重、质量控制和统一状态。

## 资源预算
对检索轮次、深度检索请求、全文精读量、工作时长及确切已知的费用设软预警与硬限制。未获实际计费数据时只报告可观测调用次数；不得虚构价格。预算到硬限制即保存检查点并请求调整。

## 重新规划
- 局部：更改查询词、优先阅读次序、替换同等权限工具、补充必要对照；在 Mission 不变和预算内自主执行。
- 重大：修改科学问题、纳排标准、交付物、硬预算、正式写入权限或长期 Workspace 结构，先取得明确许可，生成新计划版本。
- 系统性文献检索：应先冻结纳排/来源/可重复检索协议，不能为了凑满意结论任意改变标准。

## 结束准则
进入 `VALIDATING` 对照 acceptance；若证据不足，返回 `PARTIAL` 并说明具体缺口；核心工具不可用时 `BLOCKED` 或可证实的部分完成；`COMPLETED` 仅意味着约定成果合格，不是科学论断被证明。
